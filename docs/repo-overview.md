# Repo overview — the files outside the Rust API doc (rules: /AGENTS.md)

The repo is one product, PractiCal: `build/` is the Docker context (the Rust crate `practical`, its assets,
templates and locales), `e2e/` the local test harness and gates, `tests/` the image test CI runs, `deploy/` an
example deployment, `docs/` the user and developer docs. **Rust code: see the [API doc](https://xarif.gitlab.io/docker/practical/api/practical/index.html)** (local: `mise run doc`; the module
docs start at `build/src/main.rs`): request flow, module map, shared-DB rules, background loops, caches and the asset
pipeline live there. This file covers only what rustdoc does not. Line 1 of every source file states its purpose
(JS/CSS `// js/x.js —`, templates `{#- … -#}`); `rg`/`fd` skip generated, vendored and golden data (`.ignore`; `-u`).

### build/assets
- `js/**`, `css/**` = parts of app.js / style.css, order = src/bundle.rs `BUNDLES` (a new part must be listed there).
  app.js: core.js, prefetch.js, req.js, IIFE(shell/base, settings-pages, settings-connect, popovers-stream), IIFE(colors/picker,
  fields, optimise), calendar.js, `practical.editorInit = function` (editor/setup … wiring, 18 parts; runs at load
  and again after GET /editor), search.js, contacts.js, tasks.js, settings.js, IIFE(onboarding/steps, guide).
  style.css: base, frame, grid, chrome, dialogs, generic, views, icon-buttons, card-form, reminders, recurrence,
  editor-cards, links-location, tasks, settings, connect, onboarding, color-picker, color-optimiser. A Wrap part is a
  fragment of one function scope (no script alone): `onboarding/guide.js` uses `ST` and the helpers that
  `onboarding/steps.js` declares, and declaring either twice breaks the join.
- Others: history.js/.css (/history only, after app.js) · sw.js (service worker, Web Push) · theme.js (colour
  scheme before first paint) · icons.svg (sprite `<symbol id="i-…">`; `i-sort` dims an arrow via
  `--sort-up`/`--sort-down`, `i-star-h` fills via `--ico-fill`) · davx5.svg (DAVx⁵'s official logo, terms in docs/licensing.md) · icon.svg (favicon) + lettering.svg (top bar) + logo.svg (README, site; all generated, brand/) · leaflet.* (vendored 1.9.4, BSD-2,
  loaded on first map use). No inline script anywhere (CSP `script-src 'self'`).
- Client contract: `window.practical` (core.js: `$ $$ csrf esc escN escQ pad ymd parseYmd sprite ico keepCals send
  placeUnder noteRe noteHtml wheelTouch wheelAxis wheelPages swipeViews slide`; req.js: `req tell progress online
  keep authLost stash unstash guard writer copy`; prefetch.js: `prefetch prefetched intent intend stream`; shell:
  `fitPop leaving`; editor: `editorInit`), `window.{ask,askYesNo,toast,colorPicker,plural,tr,trs,MONTHS,WEEKDAYS,
  rusticalCal,rusticalEd,rusticalTasks,rusticalContacts}`; strings `window.I18N` from /assets/i18n-<lang>.js
  (placeholders `%name`, plurals via `Intl.PluralRules`; month/weekday names and date formats from `Intl`).

Client-side rules (the server side of each feature is in the module docs):

| feature | where | rule |
|---|---|---|
| views | calendar.js, frame.css | swaps `?fragment=1`, refetches on SSE; app frame = viewport, `.main` scrolls, toolbar sticky, scrollbars hidden |
| view swipe | core.js `swipeViews` (+`wheelAxis`/`wheelPages`); calendar/tasks/contacts/history.js | sideways wheel or touch swipe = click on the neighbouring view button (calendar: day…year only, no wrap); axis per touch (x iff > 2× vertical after 12 px); a horizontal scroller that can still move takes the whole touch; e2e functional/swipe.spec.mjs |
| view slide | core.js `slide`, frame.css `pc-view` | every switch between a page's views (button, swipe, calendar back/forward among day…year) = same-document view transition of `.main` only (root not captured; its toolbar with the view switch = `pc-bar`, shown at once), transform-only 240 ms; none without the API or with reduced motion (all e2e suites); cost: e2e/perf/slide.spec.mjs |
| editor | js/editor/* | view mode behind a lock; cards only where data is; status.js: TRANSP/CLASS defaults (OPAQUE/PUBLIC) shown as "default", unset stays unset, PRIORITY outside 1/5/9 keeps its number; links.js: conference hosts → join card; note.js + core.js `noteHtml`: plain DESCRIPTION, `@`contact `#`category `!`event mentions (`/api/mentions`); recurrence.js/strip.js: preview only |
| category rules | editor/categories.js, rule-editor.js, shell/settings-pages.js | applied in the client; rule editor from an event stacks over it; on /settings#categories over the page: the dialog of the scope's kind loads on first use (GET /editor, `practical.editorInit`, `rusticalEd.rule`), the other kind's is removed hidden; list redrawn via `rusticalHost.rulesChanged`; links keep the deep link `/calendar\|/tasks?rule=<name>&back=` |
| colours | js/colors/* | optimiser constants/levels in optimise.js; calendars, holidays, user-picked colours never move |
| search | search.js | debounce 180 ms, aborts stale requests, keeps answers 30 s; drop-down ≤5/kind ≤10, dialog ≤200/kind |
| title templates | editor/templates.js | new events only; ≥2 letters, 200 ms; ≤3 offers; the date stays the dialog's; UNTIL/EXDATE/RDATE/PARTSTAT/ACKNOWLEDGED not copied |
| contacts | contacts.js | sort in the client (`localStorage.ctSort`/`ctDesc`) |
| push | sw.js, settings.js | logout ends this browser's subscription |
| map | editor/location.js, map.js | asks after a 2 s typing pause or on a button; tiles tile.openstreetmap.org with attribution |
| first start | domain/onboarding.rs, routes/settings/onboarding.rs, js/onboarding/*, css/onboarding.css | one open point = one bubble beside the setting it means, red edge, no buttons but the one confirmation link; order free (`ST.pick` follows `location.hash`, not the active page). A point closes by a value only the user can have put there (`Facts`: a stored zone, a named region, an existing collection — own, else of a group the user is in) or by a mark (`confirmed`) for "what is in force is fine" — `confirm` writes NO preference, so an accepted default stays the default. The language gate is server-rendered (layout.html) and blocks; clicking a language reloads in it without answering (`try_only`). A picker saves without a page load, so the hints re-ask on `practical:prefs-saved` — the hash empties before the post lands |

## e2e/ (Playwright + harness; commands: CONTRIBUTING.md "Tests and gates")
| path | purpose |
|---|---|
| cargo.sh, build-server.sh | per-checkout cargo (AGENTS.md); server build in E2E_PROFILE (default `e2e`) + copy of the embedded assets |
| gate.sh | gate: quick (cargo+docs+functional) / full (+chaos+a11y) / visual (+baseline, compare, theme-cover; opt-in) |
| seed/ | fixture DB: 01-rustical.sh (RustiCal CLI in docker), 02-practical.py (HTTP, frozen clock); users alice/bob/carol (pw `devpass`; carol empty), group `group.familie`, fixed UUIDs `5eed0000-…`. Every person is marked through the first start (`onboarding_json` completed, in `pin()`): without it the language gate covers every page and no suite can click anything |
| first-start-db.sh | a DB in a brand-new user's state (one principal, no collections, no preferences) for judging the first start locally: `mise run dev` with `DB=~/.cache/practical-dev/first-start.sqlite3` |
| demo/ | screenshots (`mise run readme-shots`): 01-rustical.sh (emma/james, `group.family`), 02-demo.py (reuses seed/02-practical.py helpers + `pin()`; English, synthetic), shots.mjs (34 states → docs/images/NN-*.webp, 1920 px; `SHOTS=<slug,…>` retakes; GROUPS = gallery group per slug), shots.json (order, titles, captions, group; read by site/build.mjs), docs-nav.mjs (`mise run docs-nav`: back links to docs/index.md + its documentation table on every listed page; `--check` in gate-quick) |
| lib/ | axe.mjs (axe-core in the page, finding keys, allow-list; `E2E_AXE=1` + visual suite → `<state>.axe.json` audit), env.mjs (NOW = seed FROZEN), servers.mjs (dev server: DEV_LOGIN=alice, DEV_NOW=2026-10-14T08:00:00Z, DEV_POLL_MS=250, egress blocked; + non-dev login server on port+1), test.mjs (`test`, `settle()`), capture.mjs (PNG + DOM + style digest), visual.mjs, theme-cover.mjs, timing.mjs (`E2E_TIMING=1`) |
| functional/, visual/, chaos/, perf/, a11y/ | suites (`E2E_SUITE`=visual/chaos/perf/a11y, else functional); `_editor.mjs`/`_set.mjs`/`_axe.mjs` = helpers; a11y = axe-cal/axe-pages (axe states) + keys (keyboard flows, desktop light only) |
| a11y-check.mjs + a11y-allow.txt | after the a11y suite: NEW / STALE allow-list lines → exit 1 (key = contrast colour pair or target without positions/values; only shrinks) |
| compare.mjs, theme-cover.mjs (+ theme-cover-allow.txt: backlog only shrinks), baseline.sh | visual diff (pixels, DOM, computed style), dark coverage, baseline capture |
| bench/ | bench.mjs (driver, `RULES`; DB, servers, metrics, verdict and calibration in its "setup and calibration" block), client.mjs (UI interactions), gen-db.py (big synthetic DB), proc.py (CPU/RSS/wakeups/instructions per PID). Runtime: bench ~2 min, bench-compare ~3 min + build; env BENCH_ROUNDS, BENCH_UI_SAMPLES, BENCH_IDLE_S, BENCH_PHASES (server,count,idle,client), BENCH_SKIP_BUILD=1 |

Visual projects: desktop 1440×900 + phone 390×844 × light/dark (de) + `@main` states in en (desktop/phone light).
Browser frozen at NOW, Europe/Berlin, reduced motion, `Math.random` seeded, service workers blocked, no request
leaves 127.0.0.1. Pixel baselines depend on host fonts + Chromium build: compare only baselines of one machine and fixture.
